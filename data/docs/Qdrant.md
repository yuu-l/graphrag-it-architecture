## 特性

Qdrant 官方定位为向量数据库与向量相似度搜索引擎，核心能力是对高维向量进行近邻检索。它以 Rust 实现，提供 REST 与 gRPC API，并官方提供 Python、Rust、Go、Java、.NET 等多种客户端。一个 collection 中的每个 point 包含向量和可选 payload，检索时既可以使用纯向量相似度，也可以结合 payload 过滤条件。

Qdrant 支持 dense vector、sparse vector、命名向量等表示，可在同一 collection 中组合实现混合检索。相似度度量支持余弦、点积、欧氏距离、曼哈顿距离等常见方式。索引默认基于 HNSW，同时提供 scalar quantization、product quantization、binary quantization 等量化策略，用于在内存、召回率和速度之间做权衡。payload 支持多种基础类型、嵌套结构和过滤器，官方文档还描述了对 payload 建立索引以加速过滤。

在分布式能力上，Qdrant 将 collection 划分为多个 shard，并支持 replicas，以实现水平扩展与高可用。集群元数据通过 Raft 共识管理，官方文档提供了从单节点到集群的部署说明。快照可用于备份、恢复和迁移。生态上，Qdrant 与 LangChain、LlamaIndex、Haystack、FastEmbed 等工具和嵌入模型集成，适合嵌入生成、检索增强生成等工作流。

## 适用场景

Qdrant 主要面向以语义相似度为核心的检索场景，例如将文本、图片、音频等对象通过嵌入模型转换为向量后，进行语义搜索、相似项推荐和去重。由于支持 payload 过滤，它能够在向量召回的同时应用业务约束，如按时间、类目、租户或权限过滤。

在 LLM 应用中，Qdrant 常用于检索增强生成（RAG）和智能问答系统，作为外部知识库或长期记忆层，为模型提供与查询语义相近的上下文片段。官方集成和客户端库也使其容易嵌入 LangChain、LlamaIndex 等框架。

对于需要低延迟、高吞吐、可水平扩展的在线检索场景，例如推荐系统召回、实时个性化、图像/音视频指纹检索、风控相似事件查询等，Qdrant 的分布式部署和过滤能力较为契合。混合检索场景下，可以通过 dense 与 sparse 向量组合改善关键词和语义的覆盖度。

## 部署形态

Qdrant 提供 Docker 镜像，可快速单节点启动，适合开发、测试和小规模生产。单节点部署通过配置文件或环境变量控制存储、服务端口、API 密钥等，官方文档有快速开始示例。

对于生产级和大规模场景，Qdrant 支持集群部署，通过 shard 和 replica 扩展容量、吞吐并提高可用性。官方提供 Helm Chart 用于 Kubernetes 部署，并支持在分布式环境中使用 Raft 管理元数据。也可以选择官方托管服务 Qdrant Cloud，在云平台上创建和管理集群，减少运维工作。

应用侧通过 REST 或 gRPC API 访问 Qdrant，官方提供多种语言客户端。无论本地、Kubernetes 还是云托管，客户端接入方式基本一致，便于从开发环境迁移到生产环境。

## 局限

Qdrant 不是通用关系型数据库，不支持 SQL join、跨表事务和完整的关系模型。业务事务性操作、复杂关联查询仍需借助 PostgreSQL、MySQL 等系统，Qdrant 更适合作为语义检索层。

向量索引和 payload 索引会消耗内存、磁盘和 CPU 资源，尤其在未量化或高维向量规模较大时。虽然官方提供多种量化方式降低资源占用，但通常需要在召回质量、延迟和内存之间做权衡，容量规划需要结合维度、数据量、QPS 与硬件实测。

Qdrant 的查询能力以向量相似度和过滤为中心，虽然提供全文过滤等能力，但不能完全替代专用全文搜索引擎或分析型数据库。分布式运维也有一定复杂度，需要在分片、副本、一致性、网络分区、快照恢复以及索引参数调优等方面进行架构设计，且部分索引或配置调整可能涉及重建或数据迁移。
