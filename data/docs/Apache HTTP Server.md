## 特性

Apache HTTP Server（httpd）是一个模块化的 Web 服务器，核心只提供基础服务，主要功能通过在编译时静态链接或运行时动态加载模块实现。官方文档将多路处理模块（MPM）设计为可插拔组件，使服务器可以在不同操作系统上采用不同的进程、线程或混合并发模型。

配置系统基于文本指令，并支持多个配置上下文，包括服务器级、虚拟主机级、目录级以及 `.htaccess` 文件。通过 `AllowOverride` 可以控制 `.htaccess` 中的指令覆盖范围，允许不具备主配置权限的用户进行目录级配置。

Apache 提供虚拟主机能力，支持基于名称和基于 IP 的站点隔离。官方发行版还包含多种可选模块，如 `mod_ssl`、`mod_proxy`、`mod_rewrite`、`mod_auth*`、`mod_headers` 等，用于 TLS、代理、URL 重写、认证授权和响应头控制；通过 `mod_http2` 可提供 HTTP/2 支持。

## 适用场景

Apache 适合作为标准 Web 服务器提供静态内容和动态内容，尤其是经典的 LAMP 栈场景。与 PHP 等语言集成时，可以通过 `mod_php`、FastCGI 或 PHP-FPM 等机制运行动态应用。

适合需要丰富模块和细粒度控制的环境，例如复杂虚拟主机管理、基于 URL 的重写、反向代理与负载均衡、集中式访问控制以及认证授权等场景。

也适合对生态成熟度、文档完整性和平台兼容性要求较高的组织，或需要继续运行和迁移大量既有 Apache 配置与模块的环境。

## 部署形态

Apache 通常以系统服务方式部署在 Linux/Unix 或 Windows 上，主配置文件为 `httpd.conf`，并可通过 `Include` 指令拆分站点与模块配置。虚拟主机块用于在同一服务器上承载多个站点。

部署时需要选择 MPM。Unix 上常见的 MPM 包括 `event`、`worker` 和 `prefork` 等，Windows 使用 `mpm_winnt`。MPM 决定连接处理方式、进程与线程的创建方式以及资源占用特征，官方文档建议根据并发模型和模块兼容性进行选择。

在架构中，Apache 可作为前置反向代理或负载均衡入口，通过 `mod_proxy`、`mod_proxy_balancer` 或 `mod_proxy_ajp` 连接后端服务；也可以通过 `mod_ssl` 终结 TLS。容器化部署可以使用 Apache 官方发布包或操作系统包构建镜像，但容器本身不是 Apache 的内置功能。

## 局限

与传统事件驱动型服务器相比，在高并发、长连接或大量空闲连接场景下，部分 MPM 的进程/线程模型可能带来更高的内存和调度开销。官方文档建议根据工作负载选择合适的 MPM 并调整相关指令，但不会保证特定的性能参数。

`.htaccess` 提供了分布式配置能力，但如果启用，Apache 会在请求匹配的目录中查找 `.htaccess` 并重新解析指令，可能显著增加请求开销。官方文档建议在不需要目录级覆盖时设置 `AllowOverride None`。

模块丰富既是优势也是维护负担。启用过多模块会增加内存占用和攻击面，部分模块还依赖额外的系统库或构建选项。同时，Apache 配置体系灵活但历史兼容选项较多，误配可能导致性能下降或安全风险。
