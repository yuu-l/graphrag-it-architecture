# MySQL 技术选型文档

## 特性
MySQL 8.4 是 MySQL 的长期支持版本（LTS），默认存储引擎为 InnoDB，提供 ACID 事务、行级锁、外键、多版本并发控制（MVCC）和崩溃恢复等关系型数据库核心能力。其事务语义与自动恢复机制适合要求数据一致性的在线业务。

在 SQL 能力和索引方面，MySQL 8.4 支持 JSON、空间数据和全文索引，并支持公用表表达式（CTE）、窗口函数、哈希连接、不可见索引、降序索引和优化器直方图等特性。结构变更方面支持原子 DDL、CHECK 约束以及多数常见操作的在线 DDL。

在复制与高可用方面，MySQL 提供异步复制、半同步复制、组复制（Group Replication）和 InnoDB Cluster。配合 MySQL Shell、MySQL Router 可完成集群管理、故障转移和连接路由。安全和可观测性方面提供角色、TLS 加密连接、默认 caching_sha2_password 认证、Performance Schema 和 sys schema。

## 适用场景
MySQL 适合作为在线事务处理（OLTP）数据库，广泛用于 Web 应用、电商、支付、库存、账户、内容管理等需要事务一致性的业务系统。InnoDB 的 ACID 能力使其适用于读写混合和并发业务场景。

对于 Web/SaaS 类应用，可通过只读副本扩展读流量，通过主从复制或 InnoDB Cluster 提升可用性。JSON 类型允许在关系模型中存储半结构化数据，适合需要灵活结构但仍希望使用 SQL 查询的场景。

MySQL 也可作为分析系统或数据仓库的数据源，但大规模复杂分析通常需要配合 ETL、列式引擎或专用分析数据库。其核心定位仍是事务处理和业务后端存储。

## 部署形态
MySQL 8.4 支持从单机到多副本的多种部署架构：单实例适合开发、测试和小型业务；主从复制适合读扩展和冗余备份；组复制/InnoDB Cluster 提供更高可用性，并可通过 MySQL Router 实现应用接入路由和负载均衡。

在平台层面，MySQL 支持主流 Linux、Windows 和 macOS 环境，可通过官方软件仓库、二进制包或源码安装。官方提供容器镜像，可运行于 Docker 等容器环境或 Kubernetes，也可以使用云厂商的托管 MySQL 服务。

生产环境建议采用多副本部署，并配套备份、监控、告警与恢复演练。具体架构应依据可用性目标、恢复时间目标（RTO）和恢复点目标（RPO）选择，官方文档提供安装、升级、加固和性能调优指南。

## 局限
MySQL 标准复制默认是异步的，副本可能存在延迟，极端故障切换时可能丢失尚未应用的事务。半同步复制可以降低该风险，但不能完全等同于全同步；组复制提供成员级一致性，但多主模式会引入冲突检测和写放大等成本。

标准 MySQL Server（InnoDB）不具备内建的大规模水平自动分片能力，写扩展主要依赖单机性能或应用层分片。需要分布式 SQL 能力时可评估 MySQL NDB Cluster，但该方案在架构、运维和功能模型上与常规 InnoDB 部署存在差异。

在大规模复杂分析和数据仓库场景下，MySQL 相比专用分析型数据库功能有限，通常需要配合 ETL 或外部分析引擎。部分在线 DDL 操作仍可能重建表或产生锁开销；社区版也缺少部分企业级组件，如 MySQL Enterprise Backup、审计和防火墙，选型时需评估商业版或第三方补充方案。
