## 特性

Redis 是一个开源（BSD 许可）的内存数据结构存储系统，官方将其定位为数据库、缓存、消息代理和流引擎。它提供字符串、哈希、列表、集合、有序集合、流、位图、HyperLogLog、地理空间索引等数据结构，并在服务端提供原子操作，适合作为共享状态和缓存的基础组件。

Redis 内置持久化能力，支持 RDB 快照与 AOF 追加日志两种机制，可单独或组合使用。通过持久化，Redis 可以在重启后恢复数据，同时提供键过期、淘汰策略、内存上限控制等面向缓存场景的能力。

Redis 还具备复制、哨兵高可用、Redis 集群分片、发布订阅、Streams 消费者组、键空间通知和客户端缓存等能力。事务、Lua 脚本和模块系统允许在服务端扩展或组合操作，社区版之外还有 Redis Stack 等发行版提供 JSON、搜索和时间序列等扩展能力。

## 适用场景

缓存是 Redis 最典型的用法。它常作为旁路缓存，用于页面片段、会话、API 响应、热点数据等场景，通过内存访问和精细的过期/淘汰策略降低后端数据库压力并降低延迟。

Redis 可用于构建分布式应用状态，如计数器、限流器、去重、排行榜、最近活动列表和轻量任务队列。其多种数据结构可以在单次原子操作中完成状态变更，避免额外的应用层协调。

消息与流处理场景中，Redis 提供发布订阅和 Streams。Streams 支持消费者组、消息确认和按 ID 消费，适合轻量级事件流、日志流转和任务分发。

Redis 还适合实时统计、地理位置索引和短生命周期数据管理。例如在线用户状态、实时指标聚合、附近地点查询等场景，都可以利用其数据结构与过期机制。

## 部署形态

单机模式是最简单的部署方式，适用于开发、测试或低风险场景。可以开启持久化和内存上限控制，但没有自动故障转移，进程不可用时会直接影响依赖方。

主从复制模式通过一个主节点和多个副本节点提供读扩展和冗余。Redis 复制默认是异步的，副本可用于读操作和故障后的手动切换。官方高可用方案 Redis Sentinel 可在此基础上监控节点、通知客户端，并在主节点不可用时执行自动故障转移。

Redis Cluster 是官方提供的分片方案，将键分布在多个主节点上，并为每个主节点配置副本。它适合数据量或吞吐量超出单机能力的场景。集群模式要求客户端支持重定向和槽位映射，多键操作通常需要落在同一个槽。

在云和容器环境中，可采用 Redis Cloud、Redis Enterprise 或 Kubernetes Operator 等形态部署。无论自建还是托管，都应根据可用性、持久化、备份、安全和网络隔离要求选择相应架构。

## 局限

Redis 主要基于内存，数据容量受可用内存和成本约束。虽然可以持久化和淘汰数据，但需要提前规划内存上限、淘汰策略和数据集规模，否则可能触发写入拒绝或成本快速上升。

命令执行模型需要关注阻塞风险。Redis 命令执行核心通常为单线程，某些大键操作、慢查询或 Lua 脚本会阻塞其他请求，影响整体延迟。应避免在高延迟敏感场景中直接执行大范围遍历或计算密集操作。

复制和集群机制以可用性和扩展性为主，并非强一致系统。默认异步复制可能丢失故障切换前的最近写入；Redis Cluster 对跨槽多键操作支持有限，需要 hash tag 或应用层拆分。事务也不具备关系型数据库的回滚语义。

Redis 不是通用关系型数据库，不适合复杂 SQL 分析、强事务隔离、大规模离线批处理或需要复杂关联查询的场景。虽有模块扩展，但应将其定位为高性能内存数据层，而非数据仓库或 OLTP 主库替代品。
