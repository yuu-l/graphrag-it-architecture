## 特性

Django 是一个高级 Python Web 框架，官方定位为“鼓励快速开发与干净、务实的设计”。它采用“batteries-included”理念，在框架层面提供 Web 开发中常见的基础组件，减少重复造轮子的成本。

其核心功能包括对象关系映射（ORM）、URL 分发、模板引擎、表单处理与验证、用户认证与权限系统、自动管理后台、缓存框架、国际化支持、测试工具等。这些组件之间集成度较高，使用统一的配置和项目约定。

在安全方面，Django 默认提供多种防护措施，包括 SQL 注入防护、跨站脚本（XSS）防护、跨站请求伪造（CSRF）防护、点击劫持防护以及安全的密码哈希机制。官方文档强调开发者仍需遵循安全部署建议，但框架已经提供了较安全的基础默认值。

## 适用场景

Django 适合以数据模型为中心的 Web 应用，尤其是需要快速开发、清晰结构和长期维护的项目。其内置 ORM 和管理后台非常适合内容管理、新闻出版、数据平台、内部业务系统等应用。

对于需要快速构建后台管理界面的项目，Django 的自动 admin 可以显著减少 CRUD 功能开发量。管理后台可以基于模型定义自动生成列表、过滤、搜索、编辑和权限控制等界面。

如果团队以 Python 为主要技术栈，或者应用需要与数据分析、机器学习、科学计算等 Python 生态结合，Django 可以较低成本地集成这些能力。需要提供 API 时，可以使用 Django 的视图层构建接口，也可以引入成熟的第三方扩展来构建 REST 服务。

## 部署形态

Django 本身不是 Web 服务器，而是通过 WSGI 或 ASGI 接口与应用服务器通信。生产环境通常使用 Gunicorn、uWSGI 等 WSGI 服务器，或 Daphne、Uvicorn 等 ASGI 服务器运行 Django 项目，并在前置使用 Nginx 或 Apache 处理静态文件、TLS 终止、反向代理和负载均衡。

官方支持 PostgreSQL、MySQL、MariaDB、SQLite 和 Oracle 等数据库后端。SQLite 适合开发和低流量场景，生产环境通常推荐 PostgreSQL。数据库连接与凭据应通过环境变量或独立配置文件注入，避免写入代码库。

部署时必须将 `DEBUG` 设为 `False`，配置 `ALLOWED_HOSTS`，妥善管理 `SECRET_KEY`，并执行 `collectstatic` 收集静态文件。Django 也适合容器化部署，通过环境变量注入配置，并在迁移阶段执行 `migrate` 和必要的初始化任务。

## 局限

Django 的“batteries-included”设计对小型项目或纯静态 API 服务可能显得较重，项目结构、配置项和内置组件会带来一定启动成本。如果只需要简单路由和响应，轻量框架可能更合适。

虽然 Django 支持 ASGI 和异步视图，但其异步能力主要集中在请求处理栈、视图和中间件层面，部分核心组件和大量第三方应用仍以同步实现为主。对于高并发实时通信、WebSocket、长连接等场景，Django 并非最直接的选择，通常需要 Channels 等扩展或独立异步服务配合。

Django ORM 提供了较高生产力，但在复杂查询、报表分析、大规模聚合或特殊数据库特性下，可能不如手写 SQL 或专用数据访问层灵活。开发者需要关注查询数量与 N+1 问题，合理使用 `select_related`、`prefetch_related` 和索引。

Django 提供了较强的项目约定和默认结构，这有利于团队协作，但在高度定制或微服务拆分时可能限制架构灵活性。深度改造内置组件、管理后台或模板系统可能需要额外投入，并注意升级时的兼容性。
