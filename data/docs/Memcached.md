## 特性

Memcached 是一个高性能、分布式内存对象缓存系统，最初用于缓解动态 Web 应用的数据库压力。它以键值方式存储数据，数据保存在 RAM 中，因此读写延迟极低，吞吐较高，适合存放频繁访问的临时对象。

Memcached 的设计刻意保持简单：协议简单，客户端库覆盖大多数主流语言；服务端只提供键值操作，不具备复杂查询、持久化或复制能力。缓存项支持过期时间，并在内存不足时按 LRU 策略淘汰旧数据。协议中提供 CAS（check-and-set）操作，可用于并发更新控制。

在分布式方面，Memcached 本身不构建服务端集群，而是依赖客户端将键通过哈希分布到多个实例上。服务端进程多线程运行，可充分利用多核 CPU；默认监听 TCP 11211 端口，也可根据部署需求调整监听地址、端口和内存配额。

## 适用场景

Memcached 适用于缓存数据库查询结果、渲染片段、API 响应、会话数据等临时数据。通过把热点数据移入内存，可显著减少后端数据库的读负载，缩短响应时间，并在读多写少、访问热点明显的场景下提供较好的扩展性。

它特别适合允许短暂数据不一致或容忍缓存丢失的场景。例如 Web 应用中的数据库结果缓存、页面片段缓存、短期会话状态等，都可以依赖 Memcached 的过期时间和 LRU 淘汰自动管理生命周期。

需要强调的是，Memcached 不应作为持久化存储、系统记录或事实来源使用。节点重启、内存写满淘汰、网络故障都可能使缓存项消失，应用必须能在缓存失效后从后端重新加载数据。

## 部署形态

Memcached 通常以独立守护进程部署在 Linux/Unix 服务器上，通过启动参数配置内存上限、监听地址、端口和线程数。默认监听端口为 11211，管理员可用防火墙或私有网络限制访问。服务可以由 systemd、容器等方式托管。

在多节点部署中，Memcached 本身不维护节点列表、复制或故障转移，通常由客户端或中间层进行一致性哈希分片，将缓存键映射到多个 Memcached 实例。每个实例独立管理自己的内存和缓存项，节点加入或退出时由客户端重新映射键空间。

实际生产环境中常见形态包括：每台应用服务器旁部署一个本地 Memcached 实例，或独立缓存层部署多个专用实例，亦可使用云厂商提供的兼容 Memcached 协议缓存服务。无论哪种形态，都应把缓存层视为易失、可重建的加速层。

## 局限

Memcached 的数据完全驻留在内存中，没有内置持久化机制。服务重启或崩溃后数据全部丢失，因此不能替代数据库或消息队列等持久化系统。应用层必须设计好缓存回源和重建逻辑。

Memcached 的容量受节点内存限制，写入占满内存后按 LRU 淘汰旧项，可能导致热点数据被提前淘汰。单个缓存项默认最大为 1MB，虽然可以调大，但总内存和网络栈仍是硬约束。此外，它只提供简单键值语义，没有复杂数据结构、索引或查询能力。

安全方面，Memcached 默认没有认证和加密，不应当直接暴露在不可信网络中。生产环境通常通过网络隔离、防火墙规则或可选 SASL 认证来降低风险。由于没有内置复制和自动故障转移，单个节点故障会影响该节点上的缓存数据，客户端需把这类失败当作缓存未命中处理。
