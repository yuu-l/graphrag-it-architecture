## 特性

Ceph 是一个开源软件定义存储平台，基于 RADOS（可靠自治分布式对象存储）提供统一的对象存储、块存储和文件存储接口。其核心组件包括 Monitor（MON）、Manager（MGR）、OSD 和 MDS。MON 维护集群映射与仲裁，MGR 负责监控指标与外部管理接口，OSD 负责数据存储、复制、恢复与再平衡，MDS 为 CephFS 提供文件系统元数据服务。

Ceph 使用 CRUSH 算法对数据进行放置和定位。客户端可以直接计算数据所在的 OSD，不依赖中心化元数据索引，这使集群能够水平扩展到大规模节点，并支持按主机、机架、机房等故障域制定数据分布规则。

Ceph 同时支持多副本和纠删码两种数据保护机制，具备自我修复、自动再平衡和故障域隔离能力。系统还提供快照、克隆、精简配置、缓存分层、RBD 镜像以及 RADOS Gateway 多站点复制等功能，以满足不同数据保护和服务级别需求。

## 适用场景

Ceph 常用于云平台和虚拟化环境的统一存储后端。它可以通过 CSI 驱动为 Kubernetes 提供动态持久卷，也可为 OpenStack 的块存储、镜像和实例存储提供支撑，适合需要统一管理块、文件和对象数据的私有云与混合云平台。

RADOS Gateway 提供与 S3 和 Swift 兼容的对象存储接口，适合备份归档、数据湖、静态资源托管、影像和媒体归档等对象存储场景。多数应用无需改造即可通过标准协议访问 Ceph 对象存储。

RBD 适合为虚拟机和数据库提供持久块设备；CephFS 适合需要 POSIX 文件访问语义的共享文件系统，例如内容仓库、媒体处理、HPC 和共享开发环境等场景。

## 部署形态

Ceph 支持在 Linux 物理机或虚拟机上部署。官方推荐使用 cephadm 进行容器化部署和生命周期管理，它将 MON、MGR、OSD 等服务以容器方式运行，并支持引导集群、添加节点和升级维护。

在 Kubernetes 环境中，可以使用 Rook 编排和管理 Ceph 集群，由 Kubernetes 负责调度 Ceph 服务。除此之外还支持手动部署，但生产环境通常建议采用 cephadm 或 Rook 等受支持的部署工具。

高可用部署通常将控制面服务（MON/MGR）和数据面服务（OSD）分布在多个故障域。生产集群通常部署至少 3 个 MON 来保证仲裁，并将副本或纠删码分片分布在不同主机、机架或机房。对于跨地域容灾，可使用 RBD mirror 实现块设备复制，或使用 RADOS Gateway multisite 实现对象存储多站点同步。

## 局限

Ceph 的运维复杂度较高，需要理解 CRUSH、PG、OSD、复制/纠删码、恢复再平衡和性能调优等概念。出现性能抖动或故障时，需要具备较强的分布式存储排障能力。

Ceph 对硬件和网络有较明显的依赖。高性能场景通常需要 NVMe/SSD、充足内存和低延迟网络，小规模或资源受限环境可能难以发挥其优势，并且可能引入不必要的运维成本。

不同存储接口的特性、调优重点和成熟度存在差异，混合负载下需要做好容量规划、性能隔离和故障域设计。官方建议在生产环境部署前进行充分的功能验证、性能测试和容量规划。
