## 特性

Milvus 是一款开源、云原生、分布式的向量数据库，专为大规模向量数据的存储、索引与相似性检索而设计。它支持十亿级甚至更大规模的向量数据集，并提供低延迟、高吞吐的查询能力，常用于为机器学习、深度学习模型产生的向量提供持久化与近实时检索服务。

Milvus 采用计算与存储分离的分布式架构，核心组件包括数据节点、索引节点、查询节点、代理节点等，可独立水平扩展。数据通过对象存储持久化，配合消息队列实现流式写入与异步索引构建，使系统在大规模数据增长时仍能保持较好的扩展性与资源利用率。

在数据模型和检索能力方面，Milvus 基于 Collection、Partition、Field 等逻辑结构管理数据，支持标量过滤、主键去重、删除与更新、分区隔离等能力。它提供多种向量索引类型，包括 FLAT、IVF_FLAT、IVF_SQ8、IVF_PQ、HNSW、DiskANN 等，并支持 GPU 索引、稀疏向量检索、多向量混合搜索、范围搜索、分组搜索以及全文检索等高级能力。一致性级别可在 Strong、Bounded、Eventually、Session 之间配置，以适应不同业务对一致性与性能的权衡。

Milvus 提供多种语言的 SDK，包括 Python、Java、Go、Node.js 等，并提供 RESTful API 与图形化管理界面 Attu。同时，它已与 LangChain、LlamaIndex、Haystack 等主流 AI 应用框架集成，便于在检索增强生成等场景中直接使用。

## 适用场景

Milvus 适用于以向量相似性检索为核心的场景，例如推荐系统中的物品召回、以图搜图、视频或音频相似性检索、生物特征识别、化学分子相似性搜索以及反欺诈中的特征匹配等。这些场景通常需要在海量向量中快速找到最近邻或相似对象，并对召回率、延迟和吞吐有较高要求。

在大语言模型应用中，Milvus 常作为检索增强生成（RAG）的底层向量存储。它可以将企业私有知识库、文档切片或历史对话编码为向量，并在用户提问时高效检索相关上下文，帮助大语言模型生成更准确、更可信的回答。

对于需要在向量检索之外同时进行标量过滤、范围查询或多条件混合查询的场景，Milvus 也能提供较好的支持。适合需要水平扩展、长期保存大规模特征数据，并希望将向量检索能力集成到生产系统的团队使用。

## 部署形态

Milvus Lite 是面向本地开发、原型验证和小数据量场景的轻量级部署形态。它通常以 Python 库形式提供，可在本地快速启动，使用与完整 Milvus 类似的 API，适合在笔记本或开发环境中进行功能测试。

Milvus Standalone 是单机部署形态，适合中小规模生产或测试环境。用户可通过 Docker Compose 等方式在单台服务器上运行全部依赖组件，部署相对简单，但在扩展性、可用性和吞吐能力上不如分布式架构。

Milvus Cluster 是面向大规模生产环境的分布式部署形态，通常基于 Kubernetes 进行管理，可通过 Helm 或 Milvus Operator 部署。它支持计算与存储分离、组件级扩展、多副本以及滚动升级，适合需要高可用、高吞吐和海量数据管理的场景。此外，官方团队还提供全托管云服务 Zilliz Cloud，用户无需自行运维底层组件即可使用 Milvus 兼容接口。

## 局限

Milvus 的分布式部署涉及代理节点、数据节点、索引节点、查询节点以及消息队列、对象存储等依赖组件，整体架构相对复杂。与单机数据库相比，部署、监控和运维需要更多基础设施知识，尤其是在 Kubernetes 环境中运行时，对团队运维能力有一定要求。

在资源占用方面，部分索引类型和查询过程对内存、CPU 或 GPU 有较高要求。为获得较低查询延迟，常需要将热门数据或索引驻留内存，这会带来较大资源开销。此外，删除或更新数据后，需要依赖后台 compaction 等机制回收存储空间并优化索引，实时性上不及简单关系型数据库的直接修改。

Milvus 定位为向量数据库，并不提供传统关系型数据库中的完整 ACID 事务、复杂多表联接和聚合分析能力。其一致性模型通过配置在性能与一致性之间进行权衡，对于强事务、频繁更新或复杂关系建模的场景并不完全适配。使用时还应关注官方文档中关于维度、集合数量、字段数量等资源限制，确保系统设计在约束范围内。
