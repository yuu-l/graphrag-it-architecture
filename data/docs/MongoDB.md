## 特性

MongoDB 是面向文档的 NoSQL 数据库，使用 BSON 格式存储数据。其核心模型是文档与集合：一条记录可包含嵌套子文档和数组，字段结构可以在同一集合内不同文档间自然变化，因此更接近现代编程语言中的对象或 JSON 结构。官方手册将这种灵活性定位为文档模型的主要优势之一。

MongoDB 提供完整的复制与横向扩展能力。副本集（replica set）通过基于 oplog 的异步复制实现数据冗余与自动故障转移；分片集群（sharded cluster）按分片键将数据分布到多个分片，以支持大规模数据量和高吞吐量。查询能力包括二级索引、复合索引、地理空间索引、TTL 索引以及聚合管道（aggregation pipeline），用于在服务端完成过滤、转换、分组和计算。

MongoDB 还支持多文档 ACID 事务、变更流（change streams）和 GridFS。安全方面提供认证、基于角色的访问控制、TLS/SSL 网络加密、静态加密与企业级审计等能力，部分能力因社区版、企业版与 Atlas 而异。

## 适用场景

MongoDB 适合需要灵活 schema、快速迭代的数据模型，例如内容管理、商品目录、用户画像和游戏状态。文档模型允许相关数据内嵌在同一文档中，减少多表 join，写入和读取路径更加简单。

MongoDB 也适合高吞吐写入与水平扩展场景，例如物联网遥测、日志与事件采集、移动应用、推荐系统和实时分析。聚合管道和变更流可以支撑实时报表、流式处理下游消费等场景；地理空间能力同样适合位置相关应用。

需要强一致事务的应用可以使用 MongoDB 的多文档事务，但官方建议优先利用单文档原子性和数据建模处理一致性问题。总体而言，MongoDB 更适合以灵活 schema、半结构化数据或文档为中心的工作负载，而不是高度规范化、大量复杂关系 join 的传统 SQL 报表系统。

## 部署形态

MongoDB Atlas 是官方托管数据库服务，可部署在 AWS、Google Cloud 和 Azure 上，提供自动运维、备份、监控、升级和安全能力。Atlas 支持共享、无服务器和专用实例等不同规格，适合不希望自行管理数据库基础设施的用户。

用户也可以自托管 MongoDB Community Server 或 MongoDB Enterprise Server。Community Server 以 SSPL 许可发布，可自行部署使用；Enterprise Server 增加高级安全、审计、加密引擎、LDAP/Kerberos 等企业特性。官方还提供 Ops Manager（本地）和 Cloud Manager（云端）用于自动化部署、监控、备份和升级。

在生产环境中，官方推荐使用副本集而非单节点；更大的数据规模可以使用分片集群。容器化环境可通过 MongoDB Kubernetes Operator 管理，同时也有官方镜像与配置工具支持常见平台上的部署。

## 局限

MongoDB 的单条 BSON 文档最大为 16 MB，超过此限制的大对象需要拆分或使用 GridFS。文档模型的灵活性也意味着模式管理责任转移到应用层；对高度关系化、多实体频繁关联的模型，MongoDB 虽然提供 `$lookup` 等连接能力，但不能替代关系型数据库在复杂 join 场景下的成熟度。

多文档事务在 MongoDB 中可用，但并非所有场景的最佳选择。事务默认生命周期受 `transactionLifetimeLimitSeconds` 限制，默认值为 60 秒，长时间事务可能被中止；事务也会带来额外资源开销。官方通常建议在数据建模阶段通过内嵌文档和单文档原子性来减少对多文档事务的依赖。

运维与性能方面，聚合管道部分阻塞性算子默认有 100 MB 内存限制，超出需要 `allowDiskUse`；索引需要占用内存和存储，工作集与内存容量需要合理规划。分片键的选择需要谨慎，不合理选择可能导致数据倾斜或查询性能下降。另外，默认读关注为 `local`，在副本集故障回滚等情况下可能读到未达到多数提交的数据；如需更强一致性，应使用 `majority` 读关注和合适的写关注。
